# Implementation Plan: PHP Frontend Migration — Replace WordPress with Laravel

**Branch**: `002-php-frontend-migration` | **Date**: 2026-05-24 | **Spec**: [spec.md](./spec.md)

**Memory Synthesis**: [memory-synthesis.md](./memory-synthesis.md) | **ADR**: [ADR-008](../../docs/adr/ADR-008-php-frontend-migration.md)

---

## Summary

Replace the WordPress 6.4 + MySQL frontend with a Laravel 11 (PHP 8.2+) application running behind Nginx/PHP-FPM. The migration is a technology swap only — no new features, no API changes, no backend changes. The Laravel app reproduces all four existing pages (login, contacts list, contact detail, contact form) with functional parity. On completion, all WordPress and MySQL artifacts are removed from the codebase, Docker Compose, and CI.

## ApiClient Contract

All Spring Boot API calls go through `app/Services/ApiClient.php`. No controller calls `Http` directly (enforced by P0-05).

```php
class ApiClient
{
    public function login(string $username, string $password): array          // POST /api/v1/auth/login
    public function logout(string $token): void                               // POST /api/v1/auth/logout
    public function listContacts(array $filters, int $page = 0): array        // GET  /api/v1/contacts
    public function getContact(int $id): array                                // GET  /api/v1/contacts/{id}
    public function createContact(array $data): array                         // POST /api/v1/contacts
    public function updateContact(int $id, array $data): array                // PUT  /api/v1/contacts/{id}
    public function getFilterOptions(): array                                  // GET  /api/v1/contacts/filter-options
}
```

Every method uses `Http::timeout(5)->retry(3, 500)`. A failed or 5xx response throws a typed `ApiException`; a 401 response clears the session and redirects to login; a 4xx returns a structured error array. Controllers never inspect raw HTTP status codes.

## Docker Compose Changes

### Remove

```yaml
services:
  mysql:       # WordPress DB — removed entirely
  wordpress:   # WordPress frontend — removed entirely
volumes:
  mysql_data:       # removed
  wordpress_data:   # removed
```

### Add

```yaml
services:
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile          # php:8.2-fpm base image
    environment:
      APP_KEY: ${APP_KEY}
      APP_URL: ${APP_URL:-http://localhost:8888}
      APP_ENV: ${APP_ENV:-local}
      BACKEND_URL: http://backend:8080
      SESSION_LIFETIME: ${SESSION_LIFETIME:-30}
      LOG_CHANNEL: stderr
    volumes:
      - ./frontend:/var/www/html
    depends_on:
      backend:
        condition: service_healthy
    networks:
      - demo-net
    healthcheck:
      test: ["CMD-SHELL", "php artisan tinker --execute='echo 1;' || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 3

  nginx:
    image: nginx:alpine
    ports:
      - "8888:80"
    volumes:
      - ./frontend/public:/var/www/html/public:ro
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - frontend
    networks:
      - demo-net
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost/health || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 3
```

### Nginx config (`nginx/default.conf`)

```nginx
server {
    listen 80;
    server_name _;
    root /var/www/html/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass frontend:9000;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.ht { deny all; }
}
```

### Phase 2 — Core Services & Middleware

| Task | Description |
|---|---|
| 2.1 | **`ApiClient.php`**: Implement all seven public methods. Use `Http::withToken(session('token'))->timeout(5)->retry(3, 500, fn($e, $req) => !($e instanceof RequestException && $e->response?->status() < 500))`. Retry only on connection errors and 5xx; never retry 401/4xx (SEC-003). Handle 401 (clear session, throw `UnauthenticatedException`), 409 (return `['conflict' => true, 'message' => ...]`), 5xx (throw `ApiUnavailableException`). |
| 2.2 | **`Authenticate` middleware**: Check `session('token')` is present. If missing, redirect to `route('login')` with `intended` URL stored. Register on all contact routes. |
| 2.3 | **`config/services.php`**: Add `'backend' => ['url' => env('BACKEND_URL', 'http://localhost:8080')]`. All `ApiClient` base URL reads from `config('services.backend.url')`. |
| 2.4 | **`LoginRequest.php`**: `required|string|max:100` on `username` and `password`. |
| 2.5 | **`ContactRequest.php`**: `fullName` (required, max:255), `streetLine1` (required, max:255), `city` (required, max:100), `country` (required, max:100). All other fields optional, string, max:255. |

### Phase 3 — Controllers & Routes

| Task | Description |
|---|---|
| 3.1 | **`AuthController::showLogin`**: Return `view('auth.login')`. Redirect to `/contacts` if already authenticated. |
| 3.2 | **`AuthController::login`**: Validate via `LoginRequest`. Call `ApiClient::login()`. On success, store `token` and `role` in session, call `$request->session()->regenerate()` (SEC-001 — prevents session fixation), redirect to intended or `/contacts`. On failure, redirect back with error. |
| 3.3 | **`AuthController::logout`**: Call `ApiClient::logout(session('token'))`. Call `$request->session()->invalidate()` then `$request->session()->regenerateToken()` (SEC-001). Redirect to `/login`. |
| 3.4 | **`ContactController::index`**: Call `ApiClient::listContacts($filters, $page)` + `getFilterOptions()`. Pass to `contacts.index` Blade view. |
| 3.5 | **`ContactController::show`**: Call `ApiClient::getContact($id)`. Pass to `contacts.show`. |
| 3.6 | **`ContactController::create`**: Return `view('contacts.form', ['contact' => null, 'action' => route('contacts.store')])`. |
| 3.7 | **`ContactController::store`**: Validate via `ContactRequest`. Call `ApiClient::createContact($data)`. Redirect to `/contacts` on success; redirect back with errors on 4xx. |
| 3.8 | **`ContactController::edit`**: Call `ApiClient::getContact($id)`. Pass to `contacts.form` with `action = route('contacts.update', $id)`. |
| 3.9 | **`ContactController::update`**: Validate via `ContactRequest`. Call `ApiClient::updateContact($id, $data)`. Redirect to `/contacts/{id}` on success. |
| 3.10 | **`routes/web.php`**: Define all routes; apply `throttle:6,1` to `POST /login` (SEC-002 — brute-force protection, returns HTTP 429 on excess); wrap contact routes in `middleware('auth')` group; include `GET /health` closure returning `response('OK', 200)`. |

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Session/JWT lifetime mismatch | Medium | High | Set `SESSION_LIFETIME=30` (minutes) to match `JWT_EXPIRY_SECONDS=1800` (seconds). Test session expiry with a 30-minute wait or by manually expiring the Spring Boot JWT. |
| Spring Boot API unavailable during test | Low | Medium | `Http::fake()` in all unit/feature tests. `ApiClient` throws `ApiUnavailableException` → rendered as `errors/500.blade.php`. |
| CSS regression (class name mismatch) | Low | Low | Copy CSS verbatim; use identical class names in Blade templates; verify visually in smoke test. |
| `APP_KEY` missing on startup | Low | High | `Dockerfile` validates `APP_KEY` is non-empty; `docker compose up` fails fast with clear error message. |
| WordPress grep residue in `.git` history | Low | None | Grep only targets working tree, not git history. ADR-008 notes this is expected. |
| Docker networking: `frontend` cannot reach `backend` | Low | High | Both services on `demo-net` bridge. `BACKEND_URL=http://backend:8080` uses Docker service name. Verified in Phase 1.5 smoke test. |
