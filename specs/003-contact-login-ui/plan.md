# Implementation Plan: Contact & Login UI Enhancement — Red, White, and Black Theme

**Branch**: `003-contact-login-ui` | **Date**: 2026-05-27 | **Spec**: [spec.md](./spec.md)

**Research**: [research.md](./research.md)

---

## Summary

Restyle all four page types (login, contacts list, contact detail, contact form) and error pages using a red (`#CC0000`), white (`#FFFFFF`), and black (`#1A1A1A`) colour palette. The implementation is a CSS-only rewrite of `frontend/resources/css/app.css` plus minor structural additions to `layouts/app.blade.php` (dark header). No PHP logic, no API, no backend changes.

## Colour Palette (Design Tokens)

Defined as CSS custom properties on `:root` in `app.css`:

```css
:root {
  --color-primary:       #CC0000;  /* red — primary action */
  --color-primary-hover: #A80000;  /* red darker — hover */
  --color-primary-light: #FFF0F0;  /* red tint — error/notice bg */
  --color-dark:          #1A1A1A;  /* near-black — header, body text */
  --color-white:         #FFFFFF;  /* white — page bg, surfaces */
  --color-border:        #E0E0E0;  /* light grey — borders, dividers */
  --color-surface:       #F5F5F5;  /* off-white — table headers, inputs */
  --color-text-muted:    #666666;  /* grey — secondary text */
  --color-success:       #2E7D32;  /* green — success notices */
  --color-success-light: #F0FFF0;  /* green tint — success notice bg */
}
```

## Implementation Phases

### Phase 1 — CSS Design Tokens & Global Reset

| Task | Description |
|---|---|
| 1.1 | Add `:root` CSS custom properties block at top of `frontend/resources/css/app.css` with all 10 colour tokens from the palette above. |
| 1.2 | Add a minimal global reset: `*, *::before, *::after { box-sizing: border-box; }`, `body { margin: 0; font-family: system-ui, sans-serif; background: var(--color-white); color: var(--color-dark); line-height: 1.5; }` |

### Phase 2 — Header / Navigation

| Task | Description |
|---|---|
| 2.1 | In `frontend/resources/views/layouts/app.blade.php`: wrap the existing `<header>` in a new `<div class="demo-header">`. Add class `demo-nav` to `<nav>`. Add class `demo-logo` (already present) and `demo-logout-btn` (already present) to their respective elements. |
| 2.2 | In `app.css`: add `.demo-header` styles: `background: var(--color-dark); padding: 0; width: 100%;`. Add `.demo-nav`: `display: flex; align-items: center; justify-content: space-between; max-width: 960px; margin: 0 auto; padding: .75rem 1rem;`. Style `.demo-logo`: `color: var(--color-white); font-weight: 700; font-size: 1.2rem; text-decoration: none;`. Style `.demo-role-badge`: `background: var(--color-primary); color: var(--color-white); padding: .2rem .6rem; border-radius: 4px; font-size: .8rem;`. Style `.demo-logout-btn`: `background: var(--color-primary); color: var(--color-white); border: none; padding: .4rem .9rem; border-radius: 4px; cursor: pointer;` with hover using `var(--color-primary-hover)`. |

### Phase 3 — Login Page

| Task | Description |

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| CSS specificity conflict with existing rules | Low | Low | Rewrite (not patch) app.css; test all pages |
| Contrast failure on error text (`#CC0000` on `#FFF0F0`) | Low | Medium | Use bold text for error messages; confirmed 4.5:1 in research |
| `public/css/app.css` not synced | Low | High | Task 8.1 explicit sync step; Dockerfile already copies this file on build |
